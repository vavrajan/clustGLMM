PBC analysis using clustGLMM

Jan Vávra

2026-02-25

The goal of this vignette is to replicate the analysis of PBC data performed by (Vávra et al. 2024) with the use of clustGLMM package. This is the list of packages required for the analysis:

library(survival)
library(mixAK)
library(clustGLMM)

PBC910

The sequential PBC data can be found in pbcseq from library survival. We restrict ourselves only to patients who survived the first 910 days (2.5 years) similarly as (Komárek and Komárková 2014), who created PBC910 data in library mixAK. However, we need more columns than PBC910 provides so we create our data from pbcseq by taking the same rows as PBC910.

data(PBC910, package = "mixAK")
data(pbcseq, package = "survival")
data <- merge(PBC910, pbcseq, by = c("id", "day", "platelet", "spiders"))
dim(data)
#> [1] 918  24
(n <- length(unique(data$id)))      # number of subjects in the data
#> [1] 260

Next we prepare the outcomes for analysis:

data$ord_edema <- factor(data$edema, ordered = TRUE)
data$lalbumin <- log(data$albumin)
data$time <- data$day/365.24

The analysis in the paper consisted of

  • numeric serum bilirubin and albumin (both on log-scales),
  • binary indicators of blood vessel malformations in the skin (spiders) and presence of hepatomegaly or enlarged liver (hepato),
  • ordinal edema (0 = no edema, 0.5 = untreated or succesfully treated, 1 = edema despite diuretic therapy).

We create family argument to declare the type of the considered outcomes for clustGLMM analysis:

family <- c(lbili = "num", platelet = "poi", spiders = "bin")

The formulas for analysis will be the same for all outcomes. The fixed effects part will be an additive model with linear effect of time and age adjusted for different sex. All these effects are assumed to be group-specific. Finally, outcomes are joined via random intercepts.

formula <- list()
for (y in names(family)) {
  formula[[y]] <- list()
  formula[[y]]$fixed <- ~ 1 # will become ~ 0
  formula[[y]]$group <- ~ time + age + sex
  formula[[y]]$random <- ~ 1
}

Sampling MCMC using clustGLMM

Some of the key inputs for clustGLMM are already prepared (family, formula), but there still some key settings to be discussed. Non-effects parameters of the model may also be set to be group-specific. The default setting is provided by

(varying <- default_varying())
#> prec_num    c_ord InvSigma     InvQ      naY 
#>     TRUE     TRUE    FALSE    FALSE    FALSE

Only precision of the errors of numeric outcomes and ordered intercepts are considered to be group-specific parameters by default. We set the precision matrix (InvSigma) of the vector of random intercepts to be group-specific as well, but keep its Wishart prior scale matrix InvQ common to all groups. Missing outcome values will be always predicted for the current cluster the individual is assigned to.

varying["prec_num"] <- TRUE
varying["InvSigma"] <- TRUE

Next, we can choose which parameters are returned. We make just one change compared to the default setting and that is to save the predicted missing values.

save <- default_save()
save["naY"] <- TRUE

For tuning we will use settings that and param will be kept without any changes.

tuning <- default_tuning(experience = TRUE)
param <- default_param(sparse = TRUE)
# data$platelet <- round(data$platelet / 100)

Since we do not know the number of underlying clusters in advance, we set the maximal number of clusters G to 5. We also apply standardization of covariates and outcomes to ensure that priors are truly non-informative. We run a couple of randomly initialized chains for initial 1000 iterations.

set.seed(123456789)
mcmc_burnin <- clustGLMM(formula = formula, id = "id", family = family, data = data,
                         G = 10, nchains = 2, iter = 1000, 
                         varying = varying, save = save, tuning = tuning, param = param,
                         standardize = TRUE)

Vignette tutorial

Vignettes are long form documentation commonly included in packages. Because they are part of the distribution of the package, they need to be as compact as possible. The html_vignette output type provides a custom style sheet (and tweaks some options) to ensure that the resulting html is as small as possible. The html_vignette format:

  • Never uses retina figures
  • Has a smaller default figure size
  • Uses a custom CSS stylesheet instead of the default Twitter Bootstrap style

Vignette Info

Note the various macros within the vignette section of the metadata block above. These are required in order to instruct R how to build the vignette. Note that you should change the title field and the \VignetteIndexEntry to match the title of your vignette.

Styles

The html_vignette template includes a basic CSS theme. To override this theme you can specify your own CSS in the document metadata as follows:

output: 
  rmarkdown::html_vignette:
    css: mystyles.css

Figures

The figure sizes have been customised so that you can easily put two images side-by-side.

plot(1:10)
plot(10:1)

You can enable figure captions by fig_caption: yes in YAML:

output:
  rmarkdown::html_vignette:
    fig_caption: yes

Then you can use the chunk option fig.cap = "Your figure caption." in knitr.
